# Runbook 04 — MHA (Master High Availability Manager)

MHA là giải pháp cổ điển từ DeNA: 1 manager (Perl) giám sát master + tự động failover bằng cách relay events còn sót lại sang replica được chọn làm master mới. **Tốt nhất kết hợp với semi-sync replication** để hạn chế mất dữ liệu.

> Tình trạng dự án: maintenance mode (yoshinorim/mha4mysql-manager v0.58 là bản cuối). Khuyến nghị dùng **Orchestrator** cho deploy mới. Vẫn rất phổ biến trong các môi trường legacy.

## 1. Kiến trúc

```
                  ┌───────────────────────┐
                  │  Manager (mgmt host)  │  perl masterha_manager
                  └──────────┬────────────┘
                             │ SSH + MySQL TCP
       ┌─────────────────────┼─────────────────────┐
       ▼                     ▼                     ▼
   node1 (master)        node2 (replica)       node3 (replica)
   mha4mysql-node        mha4mysql-node        mha4mysql-node
```

Khi master chết:
1. Manager xác nhận chết (qua `secondary_check_script`).
2. SSH vào master cũ, copy binlog còn sót.
3. Chọn most-updated replica → relay binlog còn lại lên đó.
4. Promote replica → master mới, các replica khác `CHANGE MASTER TO` trỏ về master mới.
5. Gọi `master_ip_failover.sh` để move VIP.

## 2. Tiền đề

- Async hoặc Semi-Sync replication đã hoạt động (Runbook 01).
- SSH passwordless từ mgmt → mọi DB nodes (root).
- VIP 192.168.10.100 hiện gắn trên master.

## 3. Các bước

### B1. Trên TẤT CẢ DB nodes (node1/2/3)
```bash
bash scripts/mha/node-setup.sh
```
Cài `mha4mysql-node-0.58`, tạo user `mha`, sinh SSH key.

### B2. Setup SSH passwordless
Trên mgmt:
```bash
ssh-keygen -t rsa -b 4096 -N '' -f /root/.ssh/id_rsa
for H in node1 node2 node3; do ssh-copy-id root@$H; done
```

### B3. Trên mgmt host
```bash
bash scripts/mha/manager-setup.sh
```
Cài `mha4mysql-manager-0.58`, ghi `/etc/mha/myCluster.cnf`, sinh `master_ip_failover.sh`, chạy `masterha_check_ssh` + `masterha_check_repl`, start manager dạng background.

### B4. Verify
```bash
masterha_check_ssh   --conf=/etc/mha/myCluster.cnf
masterha_check_repl  --conf=/etc/mha/myCluster.cnf
masterha_check_status --conf=/etc/mha/myCluster.cnf      # "PING_OK"
tail -f /var/log/mha/myCluster/manager.log
```

## 4. Vận hành

### 4.1 Failover thủ công (planned switchover)
```bash
masterha_master_switch --conf=/etc/mha/myCluster.cnf \
  --master_state=alive \
  --new_master_host=node2 \
  --orig_master_is_new_slave \
  --running_updates_limit=10000
```

### 4.2 Failover tự động
Manager phát hiện master chết → tự run failover. Sau khi failover xong, MHA **tự dừng** (`--ignore_last_failover` cho phép chạy tiếp nếu vừa failover < 8h). Cần restart manager khi đã rebuild master cũ thành replica:
```bash
masterha_manager --conf=/etc/mha/myCluster.cnf \
  --remove_dead_master_conf --ignore_last_failover &
```

### 4.3 Rebuild master cũ thành replica
```bash
# Trên master cũ
systemctl start mysql
# Lấy GTID từ master mới
mysql -uroot -p -h<new_master> -e "SHOW MASTER STATUS\G"
# Trên master cũ:
CHANGE REPLICATION SOURCE TO SOURCE_HOST='<new_master>', SOURCE_AUTO_POSITION=1, SOURCE_USER='repl', SOURCE_PASSWORD='...';
START REPLICA;
```

## 5. Lưu ý quan trọng

- Cần `relay_log_purge = 0` trên replicas để MHA truy cập relay log khi failover.
- `report_host` trong `my.cnf` phải resolve được từ manager.
- `master_ip_failover.sh` đơn giản dùng `ip addr add/del` — production nên dùng Keepalived/Pacemaker để tránh dual VIP.
- MHA **không** dùng được với Group Replication / Galera (chỉ với async/semi-sync).

## 6. Rollback / tháo

```bash
masterha_stop --conf=/etc/mha/myCluster.cnf
systemctl disable mha-manager   # nếu có
# uninstall packages, xoá /etc/mha, /var/lib/mha, /var/log/mha
```
