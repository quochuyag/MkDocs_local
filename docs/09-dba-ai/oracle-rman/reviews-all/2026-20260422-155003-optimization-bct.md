# ⚡ Tối Ưu Hóa: Bật Block Change Tracking (BCT) Cho Incremental Backup

**Chế độ**: Optimization (Performance - Module 12)
**Ngày tạo**: 2026-04-22 15:50:03

## 1. Tình huống sự cố
Công ty bạn đang quản lý một cơ sở dữ liệu Very Large Database (VLDB) có dung lượng 5TB. Chiến lược backup hiện tại là:
- Level 0 (Full) vào Chủ nhật.
- Level 1 (Incremental) vào các ngày từ thứ 2 đến thứ 7.
Tuy nhiên, bạn nhận thấy thời gian chạy Incremental Level 1 mỗi ngày lên tới 8 tiếng, gần bằng thời gian chạy Level 0 (10 tiếng). Việc này làm ảnh hưởng đến hiệu năng lưu trữ I/O trong giờ làm việc.

## 2. Nhiệm vụ của bạn (DBA)
1. Tại sao Incremental Level 1 lại mất nhiều thời gian gần bằng Level 0 dù dữ liệu thay đổi hàng ngày rất ít (khoảng 50GB)?
2. Đề xuất tính năng RMAN nào để giải quyết vấn đề này.
3. Viết Action Plan cấu hình tính năng đó.

---

## 3. Hướng dẫn xử lý (Action Plan - Đáp án)

### Phân tích vấn đề
Bản chất của RMAN Incremental Backup mặc định là nó phải **scan toàn bộ tất cả các data blocks** trong database (5TB) để tìm ra những block nào có SCN lớn hơn SCN của bản backup Level 0 trước đó. Việc đọc toàn bộ 5TB dữ liệu gây tốn tài nguyên I/O và thời gian khổng lồ, dù số lượng block thực sự thay đổi chỉ chiếm 50GB.

### Giải pháp
Sử dụng tính năng **Block Change Tracking (BCT)**.
Khi BCT được bật, Oracle sẽ sử dụng tiến trình nền `CTWR` (Change Tracking Writer) để ghi nhận lại địa chỉ của các block bị thay đổi vào một file nhỏ bé gọn gàng (Block Change Tracking file). Khi chạy Incremental Backup, RMAN sẽ không cần quét 5TB dữ liệu nữa, mà chỉ cần đọc file BCT để biết đích xác block nào đã đổi và nhảy tới backup thẳng block đó. Thời gian backup có thể giảm từ 8 tiếng xuống còn 15 phút!

### Action Plan (Khắc phục sự cố)

**Bước 1: Kiểm tra trạng thái hiện tại của BCT**
```sql
SQL> SELECT status, filename FROM v$block_change_tracking;
```
*Kết quả trả về sẽ là `DISABLED`.*

**Bước 2: Bật tính năng Block Change Tracking**
Bạn có thể để file BCT trong OMF (Oracle Managed Files) hoặc chỉ định đường dẫn thủ công.
```sql
-- Nếu dùng OMF (ví dụ có tham số db_create_file_dest):
SQL> ALTER DATABASE ENABLE BLOCK CHANGE TRACKING;

-- Nếu cấu hình đường dẫn thủ công:
SQL> ALTER DATABASE ENABLE BLOCK CHANGE TRACKING 
     USING FILE '/u01/app/oracle/oradata/ORCL/bct_01.f' REUSE;
```

**Bước 3: Chạy thử và xác minh**
Lần chạy Incremental Backup đầu tiên sau khi bật BCT vẫn sẽ phải quét toàn bộ DB (vì file BCT mới được tạo và chưa có lịch sử). Tuy nhiên, từ lần chạy thứ 2 trở đi, thời gian sẽ giảm rõ rệt.
Để chứng minh BCT đang hoạt động, có thể truy vấn view `V$BACKUP_DATAFILE` sau khi backup:
```sql
SQL> SELECT file#, 
            datafile_blocks, 
            blocks_read, 
            used_change_tracking 
     FROM v$backup_datafile 
     WHERE completion_time > SYSDATE - 1;
```
*Nếu cột `used_change_tracking` là `YES` và `blocks_read` nhỏ hơn rất nhiều so với `datafile_blocks`, BCT đã thành công mỹ mãn.*
