# 🕵️ Phân Tích Log: Lỗi ORA-19504 Không Thể Tạo File (Disk Full)

**Chế độ**: Phân tích Log (Troubleshooting - Module 16)
**Ngày tạo**: 2026-04-20 13:35:07

## 1. Tình huống sự cố
Sáng thứ Bảy, bạn mở email lên và thấy một loạt cảnh báo thất bại từ hệ thống Backup ban đêm của con `MAILDB`.
Bạn mở RMAN log file ra và thấy đoạn log đẫm máu sau:

```text
Starting backup at 20-APR-26
allocated channel: ORA_DISK_1
channel ORA_DISK_1: SID=142 device type=DISK
channel ORA_DISK_1: starting full datafile backup set
channel ORA_DISK_1: specifying datafile(s) in backup set
input datafile file number=00001 name=/u01/oradata/MAILDB/system01.dbf
...
ORA-19504: failed to create file "/backup/maildb_01q23p.bkp"
ORA-27044: unable to write the header block of file
Linux-x86_64 Error: 28: No space left on device
Additional information: 3
RMAN-03009: failure of backup command on ORA_DISK_1 channel at 04/20/2026 02:15:22
```

## 2. Nhiệm vụ của bạn (DBA)
1. Xác định nguyên nhân gốc rễ (Root Cause) cực kỳ rõ ràng nằm trong đoạn log trên.
2. Viết Action Plan gồm 3 cách giải quyết (từ nhanh nhất đến bền vững nhất) để khắc phục tình trạng này cho đêm nay.

---

## 3. Hướng dẫn xử lý (Action Plan - Đáp án)

### Phân tích Log (Bắt bệnh)
Đây là một trong những lỗi kinh điển và dễ đọc nhất của RMAN.
- Dòng `ORA-19504` báo RMAN không thể tạo file backup tại ổ `/backup`.
- Nguyên nhân chí mạng nằm ở mã lỗi OS: `Linux-x86_64 Error: 28: No space left on device`.
=> **Ổ đĩa chứa đường dẫn `/backup` đã bị ĐẦY (Disk Full 100%)**. RMAN không có chỗ để ghi đè hoặc sinh file mới nên nó hủy quá trình backup.

### Action Plan (Khắc phục sự cố)

**Cách 1: Nhanh nhất (Chữa cháy tạm thời)**
Phải dọn dẹp không gian ngay lập tức để tối nay backup có thể chạy.
Vào RMAN, ép xóa các bản backup cũ hoặc các file Archivelog dư thừa:
```rman
RMAN> CROSSCHECK BACKUP;
RMAN> DELETE NOPROMPT OBSOLETE;
-- Nếu vẫn chưa đủ chỗ, xóa các archivelog đã được backup ít nhất 1 lần
RMAN> DELETE NOPROMPT ARCHIVELOG ALL BACKED UP 1 TIMES TO DEVICE TYPE DISK;
```

**Cách 2: Giải pháp Kỹ thuật RMAN (Bền vững hơn một chút)**
Kiểm tra lại xem tại sao ổ cứng lại bị đầy. Có thể do quên bật NÉN dữ liệu, làm cho file sinh ra quá to.
Hãy vào cấu hình RMAN bật Nén lên:
```rman
RMAN> CONFIGURE DEVICE TYPE DISK BACKUP TYPE TO COMPRESSED BACKUPSET;
```

**Cách 3: Giải pháp Hệ thống (Bền vững nhất)**
Nếu Data của Database phình to ra một cách hợp lý (business grow), việc ổ đĩa cũ bị đầy là chuyện đương nhiên.
- Liên hệ bộ phận System/Storage cấp thêm (Extend LUN) dung lượng cho Mount point `/backup` trên OS.
- Cấu hình lại Retention Policy xuống mức thấp hơn (ví dụ từ 7 ngày xuống còn 3 ngày) nếu dung lượng Storage là không thể thêm: `CONFIGURE RETENTION POLICY TO RECOVERY WINDOW OF 3 DAYS;`
