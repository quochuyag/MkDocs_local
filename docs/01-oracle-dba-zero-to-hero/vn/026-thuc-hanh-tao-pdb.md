# Bài 26: Thực hành - Tạo Pluggable Databases (PDBs)

## Mục tiêu thực hành
Trong bài thực hành này, bạn sẽ:
- Tạo PDB từ PDB$SEED bằng **SQL*Plus** (lệnh `CREATE PLUGGABLE DATABASE`).
- Tạo PDB từ PDB$SEED bằng **dbca** (giao diện đồ họa).
- Khám phá thông tin về các PDB vừa tạo.
- Xóa các PDB sau khi thực hành xong (dọn dẹp).

---

## Điều kiện tiên quyết
- Máy ảo `srv1` đã được khôi phục từ snapshot **"oradb CDB database"**.
- CDB database đang chạy với PDB1 sẵn có.

---

## Phần 1: Tạo PDB từ Seed bằng SQL*Plus

### Bước 1-2: Kết nối vào CDB

```bash
# Kết nối vào srv1 qua Putty với user oracle
sqlplus / as sysdba
```

### Bước 3: Kiểm tra OMF đã cấu hình chưa

```sql
-- OMF (Oracle Managed Files) giúp Oracle tự quản lý tên và vị trí file
-- DB_CREATE_FILE_DEST phải có giá trị (không NULL) thì Oracle mới biết đặt file PDB ở đâu
SHOW PARAMETER DB_CREATE_FILE_DEST
```

> 💡 **OMF là gì?** Khi `DB_CREATE_FILE_DEST` được đặt, Oracle tự sinh tên file datafile và đặt vào thư mục đó. Bạn không cần chỉ định thủ công.

### Bước 4: Tạo PDB2 bằng lệnh SQL

```sql
-- Bật hiển thị thời gian thực thi câu lệnh
set timing on

-- Tạo PDB2 từ PDB$SEED
CREATE PLUGGABLE DATABASE PDB2
  ADMIN USER pdb2admin IDENTIFIED BY ABcd##1234
  STORAGE (MAXSIZE 2G);   -- Giới hạn tối đa 2GB

set timing off
```

> 💡 **Giải thích:**
> - `ADMIN USER`: Tạo local administrator cho PDB2 (user này chỉ có trong PDB2).
> - `STORAGE (MAXSIZE 2G)`: Giới hạn tổng dung lượng PDB2 không vượt quá 2GB.
> - Vì `DB_CREATE_FILE_DEST` đã được cấu hình → Oracle tự biết đặt file ở đâu.

### Bước 5: Kiểm tra trạng thái PDB2 sau khi tạo

```sql
-- PDB mới tạo sẽ ở trạng thái MOUNTED (tức là CLOSED)
SELECT OPEN_MODE FROM V$PDBS WHERE NAME = 'PDB2';
-- Kết quả: MOUNTED
```

> ⚠️ **Lưu ý:** PDB mới tạo **KHÔNG tự động mở**. Phải dùng lệnh ALTER để mở.

### Bước 6: Mở PDB2

```sql
ALTER PLUGGABLE DATABASE pdb2 OPEN;

-- Xác nhận lại
SELECT OPEN_MODE FROM V$PDBS WHERE NAME = 'PDB2';
-- Kết quả: READ WRITE
```

### Bước 7: Kiểm tra kết nối tới PDB2 qua EasyConnect

```sql
-- Kết nối bằng phương pháp EasyConnect: //host:port/service_name
conn system/ABcd##1234@//srv1:1521/pdb2.localdomain

disconnect
```

> 💡 **EasyConnect:** Là phương pháp kết nối nhanh mà không cần cấu hình tnsnames.ora. Cú pháp: `//hostname:port/service_name`.

---

## Phần 2: Tạo PDB từ Seed bằng dbca (GUI)

### Bước 8-10: Chạy dbca và điền thông tin

Đăng nhập vào màn hình VM `srv1` với user `oracle`, mở Terminal và chạy:

```bash
dbca
```

Điền thông tin theo từng màn hình:

| Màn hình | Lựa chọn |
|----------|----------|
| **Creation Mode** | Chọn **Manage Pluggable Database** |
| **Manage Pluggable Databases** | Chọn **Create a Pluggable Database** |
| **Select Database** | Chọn `oradb` |
| **Credentials** | Username: `sys`, Password: `ABcd##1234` |
| **Create Pluggable Database** | Chọn **Create a new Pluggable database from PDB seed** |
| **PDB Identification** | PDB Name: `pdb3`; Admin user: `pdb3admin`; Password: `ABcd##1234` |
| **Pluggable Database Options** | Tích chọn **"Create default user tablespace"** |
| **Summary** | Click **Finish** |
| Kết thúc | Click **Close** |

> 💡 **Khác với SQL*Plus:** dbca **tự động mở PDB** sau khi tạo xong (không cần ALTER PLUGGABLE DATABASE ... OPEN).

### Bước 11-12: Kiểm tra PDB3

```sql
-- Kết nối lại với sysdba
conn / as sysdba

-- PDB3 do dbca tạo sẽ đã ở trạng thái READ WRITE
SELECT OPEN_MODE FROM V$PDBS WHERE NAME = 'PDB3';

-- Test kết nối tới PDB3
conn system/ABcd##1234@//srv1:1521/pdb3.localdomain
disconn
```

## Phần 3: Khám phá thông tin PDB

### Bước 13: Xem thông tin tất cả PDB kèm GUID

```sql
conn / as sysdba

col name format a10
SELECT NAME, CON_ID, OPEN_MODE, GUID FROM V$PDBS ORDER BY 1;
```

**Quan sát:**
- `PDB$SEED` luôn ở trạng thái **READ ONLY** (không thể sửa đổi).
- `GUID` là ID duy nhất của PDB, **không thay đổi** dù PDB bị di chuyển.

### Bước 14: Xem datafiles của các PDB

```sql
set pagesize 15
col c format a2
col file_name format a65

-- Hiển thị CON_ID (cột C) và tên file của mỗi PDB
SELECT SUBSTR(CON_ID,1,1) AS C, FILE_NAME
FROM CDB_DATA_FILES
ORDER BY 1;
```

**Quan sát cấu trúc thư mục:**
```
<OMF_DIR>/<CDB_NAME>/<PDB_GUID>/datafile/<auto-generated-filename>
```

> 💡 **Tại sao dùng GUID cho tên thư mục?** GUID đảm bảo tên thư mục là duy nhất và không đổi, ngay cả khi PDB được đổi tên hay chuyển sang CDB khác.

---

## Phần 4: Dọn dẹp - Xóa PDB2 và PDB3

```sql
conn / as sysdba

-- Phải đóng PDB trước khi xóa
ALTER PLUGGABLE DATABASE PDB2 CLOSE;
ALTER PLUGGABLE DATABASE PDB3 CLOSE;

-- Xóa PDB và cả datafiles
DROP PLUGGABLE DATABASE PDB2 INCLUDING DATAFILES;
DROP PLUGGABLE DATABASE PDB3 INCLUDING DATAFILES;

-- Xác nhận chỉ còn PDB1 và PDB$SEED
SELECT NAME, CON_ID, OPEN_MODE FROM V$PDBS ORDER BY 1;
```

## Bảng so sánh: SQL*Plus vs dbca khi tạo PDB

| Tiêu chí | SQL*Plus | dbca |
|---------|---------|------|
| Giao diện | Dòng lệnh | Đồ họa (GUI) |
| Tự động OPEN | ❌ Phải OPEN thủ công | ✅ Tự động OPEN |
| Kiểm soát chi tiết | ✅ Cao hơn | ⬜ Trung bình |
| Tốc độ thao tác | Nhanh (nếu thuần thục) | Chậm hơn |
| Phù hợp cho | Automation, scripting | Người mới, one-time tasks |

---

## Tóm tắt bài thực hành

1. **Tạo PDB bằng SQL*Plus:** Sau khi tạo, PDB ở trạng thái **MOUNTED** - phải `ALTER PLUGGABLE DATABASE ... OPEN` thủ công.
2. **Tạo PDB bằng dbca:** PDB được **tự động mở** sau khi tạo xong.
3. **GUID** trong `V$PDBS` là ID duy nhất của PDB, dùng để đặt tên thư mục chứa datafiles.
4. **EasyConnect:** Kết nối nhanh tới PDB cụ thể với cú pháp `//host:port/service_name`.
5. Trước khi `DROP PLUGGABLE DATABASE`, bắt buộc phải **CLOSE** PDB đó trước.

---

## Câu hỏi ôn tập

**1. Tại sao sau lệnh `CREATE PLUGGABLE DATABASE`, PDB không thể kết nối được ngay?**
> **Trả lời:**
> Sau khi thực thi lệnh `CREATE PLUGGABLE DATABASE`, Oracle chỉ mới tạo xong các datafiles và đăng ký metadata trong từ điển dữ liệu. Trạng thái mặc định ban đầu của PDB luôn là **`MOUNTED`**. Ở trạng thái này, các datafiles chưa được mở ra cho người dùng kết nối (ngoại trừ tài khoản có quyền quản trị PDB). Bạn bắt buộc phải chạy lệnh `ALTER PLUGGABLE DATABASE <pdb_name> OPEN;` để mở PDB sang chế độ `READ WRITE` thì các ứng dụng và user mới kết nối vào được.

**2. `STORAGE (MAXSIZE 2G)` trong lệnh tạo PDB có ý nghĩa gì?**
> **Trả lời:**
> Mệnh đề này thiết lập **hạn mức dung lượng lưu trữ tối đa (Storage Limit)** mà PDB đó được phép chiếm dụng trên đĩa cứng:
> - Tổng dung lượng của tất cả các tablespace (datafiles) thuộc PDB đó không được phép vượt quá 2GB.
> - Nếu các bảng trong PDB mở rộng vượt quá ngưỡng 2GB này, Oracle sẽ trả về lỗi `ORA-65114: space usage exceeds limit for pluggable database`, giúp DBA ngăn chặn tình trạng một PDB "ăn hết" dung lượng đĩa cứng của các PDB khác trên cùng một máy chủ.

**3. Tại sao Oracle dùng GUID thay vì tên PDB để đặt tên thư mục datafiles?**
> **Trả lời:**
> - **Đảm bảo tính duy nhất toàn cầu (Globally Unique):** GUID (Globally Unique Identifier - chuỗi 32 ký tự hex) là duy nhất trên toàn cầu.
> - **Tránh xung đột khi Unplug / Plug và Clone:** Trong môi trường Multitenant, bạn có thể rút một PDB ra (unplug) rồi cắm vào (plug) một CDB khác, hoặc đổi tên PDB (`RENAME`). Nếu dùng tên PDB để đặt tên thư mục, khi đổi tên PDB bạn sẽ phải đổi tên thư mục vật lý ở tầng OS rất phức tạp, hoặc dễ bị trùng tên thư mục nếu CDB đích đã có PDB cùng tên. Dùng GUID giúp cấu trúc thư mục lưu trữ luôn cố định, độc lập và an toàn tuyệt đối.

**4. Sự khác biệt lớn nhất giữa tạo PDB bằng SQL*Plus và bằng dbca là gì?**
> **Trả lời:**
> - **Bằng SQL*Plus:** Đòi hỏi DBA phải tự nắm rõ cú pháp câu lệnh, tự quản lý đường dẫn file (`FILE_NAME_CONVERT` nếu không có OMF), và sau khi tạo xong PDB ở trạng thái `MOUNTED` nên phải tự gõ lệnh `OPEN` và `SAVE STATE`. Thích hợp cho viết script tự động hóa.
> - **Bằng DBCA (Giao diện đồ họa hoặc silent):** Tự động hóa toàn bộ quy trình: tự động tính toán dung lượng, copy file, tạo administrator local user cho PDB, tự động `OPEN` PDB và tự động lưu trạng thái `SAVE STATE` ngay sau khi hoàn thành. Thân thiện và ít sai sót thủ công hơn.
