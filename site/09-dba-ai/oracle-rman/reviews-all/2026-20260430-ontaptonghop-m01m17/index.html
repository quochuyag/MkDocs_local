    Phần 2 – Flashcards: Khái niệm cốt lõi¶

    🟦 Nhóm 1: Nền tảng¶

    Câu hỏi Trả lời
    FRA warning/critical threshold? Warning 85%, Critical 97% → DB có thể HANG
    RPO vs RTO khác nhau thế nào? RPO = Mất tối đa bao nhiêu data; RTO = Mất bao lâu để khôi phục
    Khi nào BẮT BUỘC dùng ARCHIVELOG mode? Production OLTP và mọi khi cần hot backup (DB đang OPEN)
    Control file nên có bao nhiêu bản? ≥ 2 bản (multiplexing) trên đĩa vật lý khác nhau
    CONTROL_FILE_RECORD_KEEP_TIME mặc định? 7 ngày — tăng lên ≥ 30 ngày cho production
    SYSBACKUP khác SYSDBA thế nào? SYSBACKUP chỉ backup/recovery, không đọc được data user

    🟩 Nhóm 2: Backup Techniques¶

    Câu hỏi Trả lời
    Backup Set vs Image Copy — cái nào ra tape được? Backup Set ra được tape; Image Copy chỉ ra disk
    Image Copy có lợi thế gì? Dùng SWITCH ngay lập tức, không cần RESTORE, RTO siêu nhanh
    Incremental Level 1 Differential backup từ đâu? Từ Level 0 hoặc Level 1 gần nhất
    Incremental Level 1 Cumulative backup từ đâu? Luôn luôn từ Level 0 gần nhất
    Block Change Tracking (BCT) làm gì? Track các block đã thay đổi → incremental backup nhanh hơn đáng kể
    Retention Policy: chọn Recovery Window hay Redundancy? Chỉ chọn 1 trong 2 — không dùng đồng thời
    BACKUP NOT BACKED UP SINCE TIME 'SYSDATE-1' dùng để làm gì? Chỉ backup file chưa được backup trong 1 ngày — tránh backup lại lần 2

    🟨 Nhóm 3: Advanced Backup¶

    Câu hỏi Trả lời
    EXPIRED vs OBSOLETE khác nhau thế nào? EXPIRED = file vật lý mất; OBSOLETE = quá hạn retention
    Lệnh nào phát hiện EXPIRED? CROSSCHECK BACKUP
    Lệnh nào xóa OBSOLETE? DELETE OBSOLETE
    Recovery Catalog cần DB riêng không? Có — không đặt catalog trên cùng target DB
    Catalog lưu thêm gì so với Control File? Stored Scripts, lịch sử dài hạn, quản lý nhiều DB
    Encryption chỉ dùng được với loại backup nào? Chỉ Backup Set, không dùng với Image Copy
    KEEP FOREVER nghĩa là gì? Backup không bao giờ bị OBSOLETE — cần Recovery Catalog để quản lý lâu dài
    D2D2T là gì? Disk → Disk → Tape: FRA ngắn hạn + Tape dài hạn off-site

    🟥 Nhóm 4: Recovery¶

    Câu hỏi Trả lời
    RESTORE vs RECOVER khác nhau? RESTORE = lấy file ra khỏi backup; RECOVER = apply archive logs vào file
    Complete Recovery mở DB bằng lệnh nào? ALTER DATABASE OPEN (thông thường)
    Incomplete Recovery (PITR) mở DB bằng lệnh nào? ALTER DATABASE OPEN RESETLOGS
    TSPITR là gì? Tablespace Point-in-Time Recovery — khôi phục 1 tablespace về quá khứ
    TSPITR cần gì đặc biệt? Auxiliary destination — thư mục tạm để dựng Auxiliary instance
    Mất Control File → làm gì đầu tiên? SET DBID xxxxx rồi STARTUP NOMOUNT rồi RESTORE CONTROLFILE FROM AUTOBACKUP
    Redo Log group INACTIVE bị hỏng → lệnh gì? ALTER DATABASE CLEAR LOGFILE GROUP n
    DRA không hỗ trợ môi trường nào? RAC (Real Application Clusters)
    Block Media Recovery (BMR) cần gì? File backup còn hợp lệ + archive logs chứa changes của block đó

    🟪 Nhóm 5: Advanced Topics¶

    Câu hỏi Trả lời
    Linux vs AIX — endian format khác nhau không? Có: Linux/Windows = Little Endian; AIX/Solaris = Big Endian
    Khác endian thì phải làm gì khi transport? Chạy CONVERT TABLESPACE hoặc CONVERT DATAFILE
    Active Duplication cần gì? Network giữa source và destination, không cần file backup trên disk
    Duplication có thay đổi DBID tự động không? Có — RMAN tự đổi DBID cho bản clone
    Nguy hiểm nhất khi Duplication là gì? Quên DB_FILE_NAME_CONVERT → ghi đè lên Production
    CDB Root backup BACKUP DATABASE bao gồm gì? ROOT + tất cả PDB + archivelogs
    RAC: Snapshot Control File phải để ở đâu? Shared Storage (ASM) — tất cả nodes đều truy cập được
    Cloud backup bắt buộc phải làm gì? Mã hóa trước khi push lên OCI

D) Cần mã hóa backup

    30. Sau khi chạy CROSSCHECK BACKUP, một backup piece hiện trạng thái EXPIRED. Bước tiếp theo hợp lý nhất là?

    A) RESTORE lại piece đó từ tape
B) DELETE EXPIRED BACKUP để loại bỏ record không còn dùng được
C) REPORT OBSOLETE để xác nhận lại
D) RESYNC CATALOG

    Phần 4 – Fire Drills tổng hợp¶

    Fire Drill 1 — Control File bị mất hoàn toàn¶

    Bối cảnh: Database crash, toàn bộ control file mất. DBID bạn nhớ là 1234567890. Có Autobackup Control File đang bật. FRA = /u02/fra.

    Nhiệm vụ: Viết đầy đủ các bước để khôi phục và mở database.

    ▶ Xem đáp án 
    -- Bước 1: Kết nối khi DB chưa MOUNT được
rman target /

-- Bước 2: Set DBID (vì không có control file, RMAN không tự biết)
SET DBID 1234567890;

-- Bước 3: Start NOMOUNT (chỉ cần SPFILE/PFILE)
STARTUP NOMOUNT;

-- Bước 4: Restore control file từ autobackup
RESTORE CONTROLFILE FROM AUTOBACKUP;

-- Bước 5: Mount database với control file vừa restore
ALTER DATABASE MOUNT;

-- Bước 6: Restore và recover toàn bộ database
RESTORE DATABASE;
RECOVER DATABASE;

-- Bước 7: Mở database (phải RESETLOGS sau khi recover từ control file)
ALTER DATABASE OPEN RESETLOGS;

-- Bước 8: Backup ngay sau khi khôi phục
BACKUP DATABASE PLUS ARCHIVELOG;
    **Lưu ý**: Nếu không nhớ DBID, tìm trong alert log hoặc `V$DATABASE.DBID`.

    Fire Drill 2 — DROP TABLE nhầm lúc 09:00, recover về 08:55¶

    Bối cảnh: Dev vô tình chạy DROP TABLE HR.EMPLOYEES lúc 09:00 trên production. Database ở ARCHIVELOG mode, backup đầy đủ. Yêu cầu recover đúng table về thời điểm 08:55.

    Nhiệm vụ: Dùng Table Recovery (M12). Auxiliary destination = /tmp/tableaux.

    ▶ Xem đáp án 
    -- Cách 1: Table Recovery (Oracle 12c+, đơn giản nhất)
rman target /

RECOVER TABLE HR.EMPLOYEES
  UNTIL TIME "TO_DATE('2026-04-30 08:55:00','YYYY-MM-DD HH24:MI:SS')"
  AUXILIARY DESTINATION '/tmp/tableaux'
  DATAPUMP DESTINATION '/tmp/datapump'
  DUMP FILE 'recovered_emp.dmp'
  NOTABLEIMPORT;

-- Sau đó import thủ công:
-- impdp hr/hr DUMPFILE=recovered_emp.dmp TABLES=EMPLOYEES REMAP_TABLE=EMPLOYEES:EMPLOYEES_RECOVERED

-- Cách 2: REMAP ngay khi recover (nếu muốn giữ table cũ và tạo table mới)
RECOVER TABLE HR.EMPLOYEES
  UNTIL TIME "TO_DATE('2026-04-30 08:55:00','YYYY-MM-DD HH24:MI:SS')"
  AUXILIARY DESTINATION '/tmp/tableaux'
  REMAP TABLE HR.EMPLOYEES:HR.EMPLOYEES_RECOVERED;
    **Không dùng PITR toàn database** vì sẽ mất mọi data từ 08:55 đến 09:00 của các table khác.

    Fire Drill 3 — FRA đầy 100%, database treo¶

    Bối cảnh: 03:00 sáng. Alert: ORA-19809. DB vẫn OPEN nhưng mọi write transaction đang treo. FRA = 10GB, RETENTION = Recovery Window 7 Days. Không có Tape.

    Nhiệm vụ: Xử lý khẩn cấp trong 5 phút, sau đó phòng ngừa tái phát.

    ▶ Xem đáp án 
    -- Bước 1: Chẩn đoán nhanh qua SQL*Plus
SELECT FILE_TYPE,
       ROUND(PERCENT_SPACE_USED,1) AS PCT_USED,
       ROUND(PERCENT_SPACE_RECLAIMABLE,1) AS PCT_RECLAIM,
       NUMBER_OF_FILES
FROM V$RECOVERY_AREA_USAGE
ORDER BY PERCENT_SPACE_USED DESC;

    -- Bước 2: Crosscheck rồi dọn ngay
rman target /

CROSSCHECK BACKUP;
CROSSCHECK ARCHIVELOG ALL;

-- Xóa backup hết hạn
DELETE NOPROMPT OBSOLETE;

-- Nếu vẫn chưa đủ: xóa archive log đã được backup
DELETE NOPROMPT ARCHIVELOG ALL BACKED UP 1 TIMES TO DEVICE TYPE DISK;

    -- Bước 3: Tăng FRA size tạm thời (không restart DB)
ALTER SYSTEM SET DB_RECOVERY_FILE_DEST_SIZE = 20G SCOPE=BOTH;

    -- Phòng ngừa dài hạn: setup retention + auto delete
CONFIGURE RETENTION POLICY TO RECOVERY WINDOW OF 7 DAYS;
CONFIGURE ARCHIVELOG DELETION POLICY BACKED UP 1 TIMES TO DEVICE TYPE DISK;

    # Thêm vào crontab: tự dọn mỗi đêm
0 1 * * * rman target / << 'EOF'
DELETE NOPROMPT OBSOLETE;
DELETE NOPROMPT ARCHIVELOG ALL BACKED UP 1 TIMES TO DEVICE TYPE DISK;
EXIT;
EOF

    Fire Drill 4 — Datafile 4 bị corrupt, cần recover không down DB¶

    Bối cảnh: Giờ hành chính. ORA-01578: block corrupted file#4 block#202. Database OPEN, datafile 4 thuộc tablespace USERS (không critical). Có Image Copy mới nhất từ đêm qua.

    Nhiệm vụ: Recover datafile 4 mà không shutdown database.

    ▶ Xem đáp án 
    -- Bước 1: Offline datafile 4 (không cần shutdown)
ALTER DATABASE DATAFILE 4 OFFLINE;

    rman target /

-- Bước 2a: Nếu dùng Image Copy (RTO nhanh nhất)
SWITCH DATAFILE 4 TO COPY;     -- Trỏ về Image Copy
RECOVER DATAFILE 4;             -- Apply archive logs

-- Bước 2b: Nếu dùng Backup Set (không có Image Copy)
RESTORE DATAFILE 4;
RECOVER DATAFILE 4;

    -- Bước 3: Đưa datafile online lại
ALTER DATABASE DATAFILE 4 ONLINE;

    -- Bước 4 (nếu có nhiều block corrupt): Dùng DRA
LIST FAILURE;
ADVISE FAILURE;
REPAIR FAILURE;
    **Hoặc Block Media Recovery nếu chỉ vài block**: 
    RECOVER DATAFILE 4 BLOCK 202;

    Fire Drill 5 — Clone DB production sang môi trường dev qua mạng¶

    Bối cảnh: Cần tạo bản dev database ORADB_DEV từ production ORADB ngay lập tức. Không có thời gian copy backup ra disk. Destination server đã cài Oracle, listener đang chạy. DB_CREATE_FILE_DEST trên dev = /oracle/dev.

    Nhiệm vụ: Active Database Duplication.

    ▶ Xem đáp án 
    # Bước 1: Trên destination server — tạo PFILE/SPFILE tối thiểu cho auxiliary
# Thêm vào /oracle/product/12c/db/dbs/initORADB_DEV.ora:
echo "DB_NAME=ORADB_DEV" >> /oracle/product/12c/db/dbs/initORADB_DEV.ora

    # Bước 2: Startup auxiliary instance NOMOUNT
sqlplus / as sysdba << 'EOF'
STARTUP NOMOUNT PFILE='/oracle/product/12c/db/dbs/initORADB_DEV.ora';
EXIT;
EOF

    # Bước 3: Kết nối RMAN với cả 2 DB
rman TARGET sys/oracle@oradb AUXILIARY sys/oracle@oradb_dev

    -- Bước 4: Duplicate
DUPLICATE DATABASE TO oradb_dev
  FROM ACTIVE DATABASE
  PASSWORD FILE
  SPFILE
    SET DB_NAME 'ORADB_DEV'
    SET DB_UNIQUE_NAME 'ORADB_DEV'
    SET DB_CREATE_FILE_DEST '/oracle/dev'
    SET LOG_FILE_NAME_CONVERT '/oradata/oradb/', '/oracle/dev/'
    SET DB_FILE_NAME_CONVERT '/oradata/oradb/', '/oracle/dev/';
    **Sau khi hoàn tất**: RMAN tự đổi DBID của ORADB_DEV → độc lập hoàn toàn với production.

    Phần 6 – Sơ đồ quyết định Recovery¶

    SỰ CỐ XẢY RA
      │
      ▼
Xác định loại failure
      │
      ├──► Instance Crash (power off, SHUTDOWN ABORT)
      │         └─► STARTUP → Oracle tự Instance Recovery (SMON)
      │
      ├──► Media Failure (mất datafile, corruption)
      │         │
      │         ├── Có Image Copy? ──► SWITCH DATAFILE TO COPY → RECOVER (không cần RESTORE)
      │         └── Có Backup Set? ──► RESTORE → RECOVER → ONLINE
      │
      ├──► User Error (DROP TABLE, DELETE nhầm)
      │         │
      │         ├── 1 table? ──────► RECOVER TABLE ... UNTIL TIME (Table Recovery)
      │         ├── 1 tablespace? ──► RECOVER TABLESPACE ... UNTIL TIME (TSPITR)
      │         └── Toàn DB? ───────► PITR → OPEN RESETLOGS
      │
      ├──► Block Corruption (ORA-01578)
      │         │
      │         ├── 1-vài block? ──► RECOVER DATAFILE X BLOCK Y (BMR)
      │         ├── Nhiều block? ──► LIST FAILURE → ADVISE FAILURE → REPAIR FAILURE (DRA)
      │         └── Validate? ─────► VALIDATE DATABASE CHECK LOGICAL
      │
      └──► Control File mất
                └─► SET DBID → STARTUP NOMOUNT → RESTORE CONTROLFILE FROM AUTOBACKUP
                    → MOUNT → RESTORE DATABASE → RECOVER DATABASE → OPEN RESETLOGS

    Ma trận RTO vs Giải pháp¶

    Yêu cầu Giải pháp Ghi chú
    RTO < 10 phút Image Copy + SWITCH Không cần RESTORE
    RTO 1–4 giờ Backup Set + RESTORE Tốc độ phụ thuộc I/O
    RPO = 0 Data Guard SYNC Ngoài phạm vi RMAN thuần túy
    Recover 1 table Table Recovery Cần Auxiliary destination
    Recover 1 tablespace về quá khứ TSPITR Cần Auxiliary destination
    Compliance 5-7 năm KEEP FOREVER + Catalog Bắt buộc có Recovery Catalog
    Off-site backup Password Encryption + Tape Mã hóa bắt buộc trước khi rời site

    10 C LIST → ADVISE → REPAIR → CHANGE FAILURE CLOSED
    11 B Phải CONVERT trước (khác endian)

    20 B V$SESSION_LONGOPS theo dõi tiến độ operation dài

    Checklist trước khi apply production¶

    Trước khi chạy bất kỳ lệnh recovery nào trên production, kiểm tra:

    • Xác định chính xác loại failure (instance / media / user error / block)
    • Có backup hợp lệ không? (LIST BACKUP SUMMARY, CROSSCHECK BACKUP)
    • ARCHIVELOG mode đang bật? (ARCHIVE LOG LIST)
    • FRA còn dung lượng không? (V$RECOVERY_AREA_USAGE)
    • Cần Complete hay Incomplete Recovery?
    • Nếu PITR → thông báo users về khoảng thời gian bị mất data
    • Auxiliary destination có đủ space không? (cho TSPITR / Table Recovery)
    • Sau recovery → backup ngay lập tức
